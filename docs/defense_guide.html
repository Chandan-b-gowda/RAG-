02What is RAG?

Retrieval-Augmented Generation — the core idea of the whole project.

RAG is made of two steps, and the name tells you both:

  • Retrieval = first, find the most relevant pieces of text from your document.
  • Generation = then, a language model (Gemini) writes an answer using those pieces.

So instead of the AI answering from memory, it first looks things up, then answers based on what it found.

Analogy — the open-book exam

Imagine two students in an exam. Student A answers everything from memory — sometimes right, sometimes confidently wrong. Student B is allowed to open the textbook, find the right page, and answer from it — and can point to the exact line.

A plain chatbot is Student A. Your RAG system is Student B. Retrieval is "finding the right page"; generation is "writing the answer from it."

03Why RAG is needed

The problem it solves — this is the "why" behind your whole project.

Ordinary large language models (like a plain ChatGPT) have three real weaknesses. RAG fixes all three:

Plain LLM — the problems

1. It hallucinates. It can make up facts that sound convincing but are wrong.

2. It doesn't know your documents. It was trained on public internet text, not your company handbook or your PDF.

3. You can't check it. It gives no source, so you can't verify the answer.

RAG — the fixes

1. Grounding. It answers only from retrieved text, so it invents far less.

2. Your data. It searches your uploaded document, so it knows private/new information.

3. Citations. It shows the exact passage, so answers are verifiable and trustworthy.

Say this

"RAG matters because language models hallucinate and can't see private documents. By retrieving real passages first and forcing the model to answer from them, we reduce hallucination and can cite sources — which is essential for trustworthy answers."

04How it works in your project

The actual pipeline you built, step by step.

Your system has two phases. The first happens once, when a document is uploaded (ingestion). The second happens every time someone asks a question (query).

Phase 1 — Ingestion (preparing the document)

  1. Read the PDF.

    Extract the raw text from the file (using PyPDF).

  2. Split into chunks.

    Cut the text into small overlapping pieces (~1000 characters). Models can't read a whole book at once, and small focused pieces are easier to search.

  3. Create embeddings.

    Turn each chunk into a list of numbers (a "vector") that captures its meaning. Done locally and free with Sentence-Transformers.

  4. Store in the vector database.

    Save all those vectors in Chroma so they can be searched instantly.

Phase 2 — Query (answering a question)

  1. Embed the question.

    Turn the user's question into a vector the same way.

  2. Semantic search.

    Find the handful of chunks whose vectors are closest to the question's vector — i.e. the passages that mean the same thing. This is "top-k" retrieval (k = how many, e.g. 4).

  3. Build a grounded prompt.

    Put those passages plus the question into a carefully written instruction that says: "Answer using only this context, and cite it. If it's not here, say you don't know."

  4. Generate the answer.

    Send that to Gemini (via Google Cloud Vertex AI). It writes the answer and adds citations like [1], [2].

Key point

The language model is never trained or changed in this project. We don't teach it your document — we simply hand it the relevant passages at question time. That's the whole trick, and it's why RAG is fast and cheap compared to training a model.

05Key concepts, simply

Short, plain definitions for the words you'll be asked about.

Embeddingtext → numbers

A list of numbers representing the meaning of a piece of text. Similar meanings get similar numbers, so we can measure how related two texts are.

Vectorthe list itself

Just the name for that list of numbers. "Vector" and "embedding" are used almost interchangeably.

Chunka slice of text

A small piece of the document (~1000 characters). We split documents into chunks so retrieval stays focused and fits the model.

Vector databaseChroma

A special store that holds embeddings and can instantly find the ones most similar to a query. Ordinary databases can't do this well.

Semantic searchmeaning search

Searching by meaning, not exact keywords. "How much holiday?" can match a passage about "annual leave" even with no shared words.

Top-kk = 4

How many chunks we retrieve for each question. More gives more context but can add noise.

Grounded promptthe instruction

The wording we send the model telling it to answer only from the provided passages and to admit when the answer isn't there.

Hallucinationmade-up facts

When a model states something false with confidence. The main problem RAG is designed to reduce.

LLMGemini

Large Language Model — the AI that understands and writes text. Yours is Google's Gemini, accessed through Vertex AI.

Temperature= 0

A setting for how "creative" the model is. You set it to 0 so answers are factual and repeatable, not imaginative.

07Google Cloud's role

Your supervisor will specifically ask this — here's the clear answer.

Google Cloud is where the "brain" of your system lives. The language model that writes answers, Gemini, is too large to run on a laptop. Google runs it in their data centres, and you access it over the internet through a service called Vertex AI.

What is Vertex AI?

Vertex AI is Google Cloud's platform for using AI models. In your project it does one specific job: it's the doorway to Gemini. Your code sends the question + retrieved passages to Vertex AI, and Vertex AI returns Gemini's answer.

How does it help your project?

Access to a powerful model

You get a state-of-the-art model (Gemini 2.5 Flash) without owning expensive hardware.

Managed & reliable

Google handles the servers, scaling, and uptime. You just make a request.

Secure login

Instead of a password in your code, it authenticates through your Google identity (gcloud login) — safer.

University credits

Your usage is billed to an education credit, so running experiments costs you nothing.

The model runs in Google's data centres; my code sends the question and the retrieved passages to Vertex AI and gets back the generated answer. It gives me a powerful model without local hardware, handles security through my Google login, and my usage runs on a university education credit."

Handy distinction if asked: there are two ways to reach Gemini — a simple "API key" (Google AI Studio) and the fuller "Vertex AI" on Google Cloud. You use Vertex AI because it works with your university's Google Cloud credits and is the more professional, production-grade route.

08What you tested, and what you found

The research 30% — your measurable contribution.

You didn't just build the app; you measured it. You created a test set of 18 questions about a sample document (14 with known answers, 4 deliberately unanswerable to test honesty), and used the model itself as an automatic grader. Three experiments:

Research questionWhat you variedResult
RQ1 — Does RAG beat a plain LLM?Retrieval ON vs OFFRAG 94% vs plain 44%
RQ2 — Does chunk size matter?500 / 1000 / 1500 chars94% / 94% / 100%
RQ3 — Does retrieving more help?top-k = 2 / 4 / 897% / 94% / 97%

Headline finding (RQ1): RAG more than doubled accuracy (44% → 94%). The plain model failed on document-specific facts and invented answers for the unanswerable questions; RAG grounded its answers and correctly said "I couldn't find this."

The honest finding (RQ2 & RQ3): chunk size and top-k made almost no difference here — all within one question of each other. The right interpretation is not "1500 is best"; it's that on a small, clean document with a strong model, retrieval finds the answer under almost any setting. These knobs matter more on large, noisy collections.

This earns marks

Saying "the differences in RQ2/RQ3 are within noise, so I won't over-claim" shows scientific honesty. Also mention the limitation of the automatic grader: it's an AI grading an AI, so you'd validate it by hand-checking a sample. Naming your own limitations is a strength, not a weakness.

09Why doing this matters

The "what's the use of this?" question.

Practically: grounded, source-cited question-answering over private documents is one of the most in-demand AI capabilities in industry right now — think searching legal contracts, medical guidelines, company policies, or research papers. Your project is a working reference implementation of exactly that pattern.

Academically: hallucination and trust are active, important research problems for AI. Your work adds concrete evidence on how much RAG helps and how its settings affect quality — with a reusable test set others can build on.

For your degree: it draws together software architecture, machine learning, natural language processing, information retrieval, and cloud computing — the core competencies of your M.Sc.

10Likely viva questions

Click each to reveal a strong, simple answer. Practice saying them in your own words.

QIn one sentence, what is your project?

"A web app where you upload a PDF and ask questions, and it answers using only that document and cites the exact source — built using Retrieval-Augmented Generation, which I also evaluated against a plain language model."

QWhy not just use ChatGPT / Gemini directly?

"A plain model doesn't know my private document, and it can hallucinate with no way to check it. RAG retrieves the real passages first, so the answer is grounded in my document and comes with a citation I can verify. My experiment showed this raised accuracy from 44% to 94%."

QWhat is an embedding, in simple terms?

"It's a way of turning text into a list of numbers that captures its meaning. Texts with similar meaning get similar numbers, so the computer can measure how related a question and a passage are — even if they use different words."

QWhy do you split documents into chunks?

"Two reasons: a model can only read a limited amount of text at once, and searching works better on small focused passages than on a whole document. I use overlap between chunks so a sentence isn't cut in half at a boundary."

QWhat is a vector database and why not a normal one?

"A vector database (I used Chroma) stores embeddings and can instantly find the ones most similar in meaning to a query. A normal database matches exact values or keywords; it can't measure meaning-similarity, which is what semantic search needs."

QHow does your system avoid hallucination?

"Three ways: I retrieve real passages and instruct the model to answer only from them; I set temperature to 0 so it stays factual; and the prompt tells it to reply 'I couldn't find this' when the answer isn't in the context. In testing it correctly refused all the unanswerable questions."

QWhat is the role of Google Cloud in your project?

"Google Cloud, via Vertex AI, is how I access the Gemini language model — it runs in Google's data centres, not on my laptop. My code sends the question and retrieved passages to Vertex AI and gets back the answer. It gives me a powerful model without local hardware, secure login through my Google identity, and it runs on my university education credit."

QWhy Vertex AI rather than a simple API key?

"Both reach Gemini. Vertex AI is the Google Cloud route that works with my university's cloud credits and is the more production-grade, professional option, with authentication tied to my Google identity instead of a key pasted in the code."

QDid you train or fine-tune the model?

"No — and that's the elegance of RAG. I never change the model. I just give it the relevant passages at question time. That makes the system fast to build, cheap to run, and easy to update: to add knowledge I just add documents, not retrain anything."

QHow did you evaluate it, and what did you find?

"I built a test set of 18 questions with known answers, including unanswerable ones, and used an automatic LLM grader. RAG scored 94% versus 44% for the plain model. Chunk size and top-k had little effect on my small clean document — a result I report honestly rather than over-claiming."

QWhat are the limitations of your work?

"My test set is small and based on one synthetic document, so results demonstrate the effect rather than prove a general number. My grader is an AI judging an AI, which I'd validate with manual checks. And chunking/top-k effects would show more clearly on larger, noisier document collections."

QWhat is semantic search?

"Search by meaning rather than exact keywords. Because both the question and the passages are embeddings, I can find passages that mean the same thing even when they share no words — 'how much holiday' matches 'annual leave'."

QHow would you improve or extend it?

"A larger and harder test set; validating the automatic grader by hand; supporting more file types; deploying it online; and trying a 're-ranking' step that re-orders retrieved passages for even better relevance."

QWhat does 'top-k = 4' mean?

"For each question I retrieve the 4 most relevant chunks and give those to the model. k is just how many passages I fetch — I tested 2, 4, and 8 to see if more context helps."
